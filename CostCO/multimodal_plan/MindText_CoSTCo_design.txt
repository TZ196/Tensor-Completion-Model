MindText-CoSTCo / MindText-GCN-CoSTCo Design Plan
=================================================

1. Goal
-------

The project has three existing tensor-completion baselines:

1. CoSTCo
   Input: source_id, destination_id, time_id.
   Output: traffic value X[i,j,t].

2. TopoFeature-CoSTCo
   Input: source_id, destination_id, time_id, hand-crafted topology features.

3. GCN-CoSTCo
   Input: source_id, destination_id, time_id, and dynamic adjacency A_t.

The MindText extension adds a text modality inspired by MindTS, but adapts it
to satellite path-traffic tensor completion.

Current priority backbone:

rank = 50
nc = 64
node_dim = 64
gcn_dim = 128
lr = 0.001


2. Modalities
-------------

For a tensor entry X[i,j,t], the model can use:

1. Flow / KPI modality
   The latent CoSTCo representation learned from source_id, destination_id,
   and time_id.

2. Topology modality
   The dynamic adjacency matrix A_t, encoded by the GCN branch.

3. Text modality
   Endogenous time-slice text and exogenous experiment-background text.


3. Leakage Policy
-----------------

The text preparation pipeline is independent from the random train/validation
/test mask.

Endogenous text generation must not read:

1. sat_path_bytes_mb_tensor.npy traffic values.
2. Train/validation/test split files.
3. Masked visible traffic statistics.
4. Validation or test target values.
5. Full-slice traffic mean, max, top-k, source IDs, or destination IDs.

Random masking is used only by model training runners. It is not part of text
generation.


4. Endogenous Text
------------------

Current implementation:

Endo-Topo only.

Source:

sat_connectivity_tensor_dynamic_60s_1000ms.npz

One endogenous paragraph is generated per time slice.

Allowed topology fields:

1. time_index
2. num_satellites
3. edge_count_undirected
4. edge_count_directed_entries
5. avg_degree
6. min_degree
7. max_degree
8. is_connected
9. avg_shortest_path_hops
10. diameter_hops
11. changed_adjacency_entries_from_prev
12. changed_edges_from_prev

t = 0 boundary:

changed_edges_from_prev = 0. The text should either state that no previous
slice is available or describe zero change relative to the initialization.

Risk:

The topology changes sparsely over 60 seconds, so the 60 endogenous paragraphs
may be semantically similar. Therefore, text embedding diagnostics must be run
before interpreting model results.

Possible future topology-only enrichments:

1. Top-3 degree-central satellites.
2. Clustering coefficient.
3. Shortest-path hop histogram summary.
4. Relative changes in diameter or shortest-path statistics.
5. Sliding-window topology summaries over 3-5 seconds.

These additions remain leakage-safe because they use only A_t.


5. Exogenous Text
-----------------

Source:

experiment_description.md

DeepSeek summarizes this configuration file into static global text segments.
These segments are not time-varying.

Typical segment roles:

1. C1 simulation setup
2. C2 constellation configuration
3. C3 topology generation
4. C4 routing policy
5. C5 link capacity
6. C6 traffic generation
7. C7 tensor completion task

Boundary between exogenous and endogenous text:

Exogenous text describes static or global mechanisms, such as simulation setup,
constellation configuration, routing policy, link capacity, and task semantics.

Endogenous text describes the measured topology state at a specific time t.

This boundary is important for cross-view attention:

Query = dynamic endogenous time-slice text.
Key/Value = static exogenous background segments.


6. Text Generation And Encoding
-------------------------------

DeepSeek is used for text content generation:

1. Generate exogenous segments from experiment_description.md.
2. Generate endogenous time-slice paragraphs from topology-only statistics.

The embedding encoder is a separate component.

Current implementation:

encode_satellite_texts.py uses a deterministic hashing bag-of-words baseline.

Current embedding dimension:

embedding_dim = 256

The model then projects text embeddings before fusion:

text_projection_dim = 64 or 128

This means:

offline encoder: text -> 256-dimensional embedding
model projection: 256 -> 64/128-dimensional trainable representation

If local semantic encoder weights are available, a sentence embedding model
such as all-MiniLM-L6-v2 is preferred for final semantic experiments. Hashing
BoW is a reproducible no-network baseline and should not be used alone to
conclude that text semantics are ineffective.

Normalization:

The current hashing encoder writes normalized embeddings and records metadata.
For sentence-transformer embeddings, use L2 normalization before saving.


7. Text Branch Execution Order
------------------------------

The implementation exposes staged options, but the final text branch order is:

1. Optional segment-level content condenser.
2. Cross-view attention.
3. Optional semantic gating.
4. Text projection before fusion with flow/graph features.
5. Optional temporal semantic alignment loss.

This resolves the stage-order ambiguity: the stages are introduced gradually
for experiments, but the full model executes condenser before cross-attention.


8. Stage 1: Concat Baseline
---------------------------

Purpose:

Verify whether text embeddings help before adding complex interaction modules.

For CoSTCo + text:

z_flow[i,j,t] || z_text_proj[t] -> MLP -> traffic

For GCN-CoSTCo + text:

z_flow[i,j,t] || z_graph[i,j,t] || z_text_proj[t] -> MLP -> traffic

Concat text construction:

z_text_raw[t] = E_endo[t] || mean(E_exo[1:M])
z_text_proj[t] = MLP(z_text_raw[t])

The projection is required to reduce the 256-dimensional text embedding into a
smaller trainable representation and avoid text-dimension dominance.


9. Stage 2: Cross-View Attention
--------------------------------

Purpose:

Let the current time-slice endogenous text select relevant exogenous global
knowledge.

Implementation:

Q = Dense(E_endo[t])
K = Dense(E_exo[1:M])
V = Dense(E_exo[1:M])

Z_cross[t] = softmax(QK^T / sqrt(d)) V

Current implementation:

single-head cross-attention

Equivalent setting:

num_heads = 1

If cross-attention proves useful, a later ablation can add:

num_heads = 2 or 4


10. Stage 3: Semantic Gating
----------------------------

Purpose:

Filter noisy text dimensions after cross-view fusion.

Implementation:

gate[t] = sigmoid(MLP(Z_text[t]))
Z_gated[t] = gate[t] * Z_text[t]


11. Stage 4: Segment-Level Content Condenser
--------------------------------------------

Purpose:

Learn which exogenous text segments are useful for the current time slice.

Implementation idea:

score_t[m] = MLP([E_endo[t] || E_exo[m]])
alpha_t = softmax(score_t)

Engineering safeguards:

1. epsilon smoothing:
   alpha = (1 - eps) * alpha + eps * uniform

2. residual fusion:
   E_exo_final = (1 - condenser_alpha) * mean(E_exo)
               + condenser_alpha * condensed_exo

Current defaults:

condenser_epsilon = 0.05
condenser_alpha = 0.5

The term should be consistently called Segment-level Content Condenser.


12. Stage 5: Temporal Semantic Alignment
----------------------------------------

Purpose:

Align text with flow and graph representations while avoiding false negatives
from neighboring time slices.

Loss definitions:

L_flow_text = InfoNCE(z_flow_time[t], z_text_time[t])
L_graph_text = InfoNCE(z_graph_time[t], z_text_time[t])

Do not force direct flow-graph alignment in the first version. Flow and graph
carry different information; text is used as the semantic bridge.

Time aggregation:

z_flow_time[t] = mean pooling of z_flow[i,j,t] for samples in the batch.
z_graph_time[t] = mean pooling of z_graph[i,j,t] for samples in the batch.
z_text_time[t] = mean pooling of z_text[t] for samples in the batch.

InfoNCE masking:

Positive pair:

same time t

Ignored near-time negatives:

|t - t'| <= temporal_delta, excluding the diagonal.

Valid negatives:

|t - t'| > temporal_delta

Recommended settings:

alignment_temperature = 0.2
temporal_delta = 2
alignment_projection_dim = 128

Loss weights should be tuned conservatively:

flow_text_loss_weight = 0.0, 0.001, 0.005, 0.01
graph_text_loss_weight = 0.0, 0.001, 0.005, 0.01

Training note:

Contrastive loss can be disabled for early epochs or early experiments. First
establish a stable prediction baseline, then enable alignment.

Batch note:

Random OD sampling may produce noisy time-level means. If contrastive alignment
is important, add a time-stratified sampler later so each batch covers enough
distinct time indices and enough samples per time.

14. Required Ablations
----------------------

1. no text
   Existing GCN-CoSTCo baseline.

2. real text
   Endogenous + exogenous text generated from allowed topology/configuration
   information.

3. zero text embedding
   Replace all text embeddings with zeros. This tests whether gains come from
   extra parameters alone.

4. random text embedding
   Same embedding shape, random normalized values.

5. shuffled endogenous text
   Shuffle E_endo[t] across time. This tests whether time-text alignment
   matters.

6. concat
   Direct text fusion baseline.

7. cross-view attention
   Tests whether endogenous/exogenous interaction helps.

8. semantic gating
   Tests whether text filtering helps.

9. segment-level content condenser
   Tests whether segment selection helps.

10. contrastive alignment
    Tests flow-text and graph-text semantic alignment.

Future optional ablation:

Frozen GCN-CoSTCo backbone + text-only fine-tune.


15. Pre-Training Text Diagnostics
---------------------------------

Before training text models, inspect:

1. cosine similarity over 60 endogenous embeddings
2. adjacent-time similarity
3. far-time similarity
4. random/shuffled controls
5. embedding shape and normalization metadata

If real endogenous embeddings are nearly identical across time, improve the
topology-only text statistics or switch to a semantic sentence encoder before
interpreting model results.


16. First Experimental Route
----------------------------

Recommended order:

1. GCN-CoSTCo no text.
2. GCN-CoSTCo + Text concat real.
3. GCN-CoSTCo + Text concat zero.
4. GCN-CoSTCo + Text concat random.
5. GCN-CoSTCo + Text concat shuffled_endo.
6. GCN-CoSTCo + Text cross_attention.
7. GCN-CoSTCo + Text cross_attention + flow-text alignment only.
8. GCN-CoSTCo + Text cross_attention + graph-text alignment only.
9. GCN-CoSTCo + Text cross_attention + both alignments.
10. GCN-CoSTCo + Text segment_condenser + selected alignment setting.

Only add multi-head attention after single-head cross-attention shows a clear
benefit over concat.
